# ADR-0002. Асинхронная очередь событий между API и планировщиком

**Дата:** 2026-09-04
**Статус:** принято

## Контекст

Backend API при выдаче книги должен инициировать отложенное действие —
напоминание за 3 дня до срока возврата. Планировщик работает в отдельном
контейнере. Возможны два способа связи.

## Рассмотренные варианты

1. Синхронный HTTP-вызов: API при создании выдачи сразу дёргает
   планировщик через REST.
2. Асинхронная очередь событий: API публикует событие `LoanCreated`,
   планировщик его подписывается.

## Решение

Вариант 2.

## Последствия

**Плюсы:** API не блокируется при недоступности планировщика; легко
добавить новых подписчиков (например, сервис аналитики); планировщик
сам решает, когда обрабатывать событие.

**Минусы:** нужен брокер RabbitMQ, добавляется операционная сложность;
согласованность становится eventual — напоминание может опоздать на
секунды.

**Что станет неверным, если решение пересмотреть:** диаграммы C4
Container и Dynamic, диаграмма последовательности в ПР2.
