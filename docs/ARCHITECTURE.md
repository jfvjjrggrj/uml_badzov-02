# ИС библиотеки. Архитектурная документация

## 1. Назначение и границы

ИС библиотеки автоматизирует работу вузовской библиотеки. Система
ведёт каталог книг и экземпляров, оформляет выдачу и возврат,
управляет бронями, рассчитывает пени за просрочку, списывает
устаревший фонд и импортирует библиографические записи из Каталога РГБ.

Внутри границ системы: каталог, выдачи, брони, пени, списание, импорт.
Снаружи: читатель, библиотекарь, Каталог РГБ, SMS-шлюз, SSO вуза.
Платёжный шлюз в систему не входит — пени оплачиваются в кассе.

## 2. Заинтересованные стороны и их цели

| Актёр | Кто это | Первичный? | Зачем приходит |
|-------|---------|------------|----------------|
| Читатель | студент или преподаватель | да | найти и получить книгу, продлить бронь |
| Библиотекарь | сотрудник абонемента | да | выдать, принять возврат, вести фонд |
| Каталог РГБ | внешний сервис | нет | поставляет библиографические записи |
| SMS-шлюз | внешний сервис | нет | доставляет напоминания |
| SSO вуза | внешний сервис | нет | аутентифицирует пользователей |

## 4. Модель предметной области

Диаграмма классов — `docs/02-domain/domain.puml`.

Ключевые решения:
- Экземпляр — композиция в Книгу (ADR-0001).
- Состояние экземпляра — enum `Состояние` из четырёх значений.
- Политика выдачи вынесена в отдельный класс `ПолитикаВыдачи`.

## 6. Архитектура

### 6.1 Контекст (C4 L1)
`docs/06-c4/01-context.puml`. Одна система в центре, два актёра,
три внешние системы.

### 6.2 Контейнеры (C4 L2)
`docs/06-c4/02-container.puml`. Семь контейнеров: SPA, АРМ, API,
планировщик, БД, поиск, очередь.

### 6.3 Компоненты (C4 L3)
`docs/06-c4/03-component.puml`. Семь компонентов внутри Backend API.

### 6.4 Развёртывание
`docs/06-c4/05-deployment.puml`. Kubernetes, отдельные серверы
для БД, поиска, брокера.

## 7. Архитектурные решения

- ADR-0001 — экземпляр отдельной сущностью.
- ADR-0002 — асинхронная очередь между API и планировщиком.
- ADR-0003 — поиск через OpenSearch, а не SQL LIKE.

## 8. Что осталось за рамками

- **Оплата пеней** — вне системы, оплачивается в кассе.
- **Печать инвентарных карточек** — на стороне АРМ библиотекаря,
  не моделируется.
- **Интеграция с бухгалтерией** — не рассматривалась.
- **Мобильное приложение читателя** — потенциальный будущий контейнер,
  сейчас не выделен.
- **Полнотекстовый поиск по содержанию книг** — вне задачи,
  только по метаданным.
